# Codex 工具箱

**为指定 Codex 会话选择不同模型通道，而不改变其他会话。**

Windows 本地辅助工具。它把“全局默认通道”和“已有会话的单独通道”分开管理：新会话按全局默认创建；已存在的会话可以按需固定到某个已配置的供应商、模型和思考强度，也可以手动同步回当前全局默认。

> **Codex Toolbox for Windows**: per-session provider, model, and reasoning selection for existing Codex tasks, plus provider health checks and a local customizable background experiment.

[下载 Windows 测试版](https://github.com/dgj482/codex-toolbox/releases/latest) · [查看使用手册](docs/使用手册.md) · [报告问题](https://github.com/dgj482/codex-toolbox/issues/new?template=bug_report.yml)

> `0.1.0-beta` Windows x64 测试版。社区项目，非 OpenAI 官方产品，也不代表 OpenAI 认可。会话路由与本地外观均为默认关闭的非官方实验，Codex 更新后可能失效。

| 适合谁 | 能解决什么 |
| --- | --- |
| 同时维护多个 Codex 任务的人 | 不同任务保留不同模型通道和推理强度，不干扰彼此 |
| 配置了多个 API 或本地模型服务的人 | 一次检测全部已配置通道，再决定使用哪一个 |
| 想把 Codex 窗口做得更个性化的人 | 本地图片、GIF、MP4 背景可按显示范围和通透效果调节 |

## 它解决什么问题

Codex 的全局通道适合决定**之后新建的会话**，但不适合管理已经在进行中的不同任务。工具箱的核心是把每个已有会话的选择明确展示出来。

```text
全局默认通道 ──────────────> 之后新建的会话

已有会话 A ── 固定 ────────> 供应商 1 / 模型 1 / 思考强度 1
已有会话 B ── 固定 ────────> 供应商 2 / 模型 2 / 思考强度 2
已有会话 C ── 跟随全局 ────> 当前全局默认通道
```

例如，可以让长期代码任务保持当前官方登录通道，同时把独立研究任务固定到自行配置的其他 API 通道。调整其中一个会话不会自动改写其余会话。

## 为什么值得用

- **把模型选择留在任务上，而不是留在全局设置里。** 每个已有会话可单独固定供应商、模型和思考强度；复杂任务用更强模型，简单整理或重复性任务可选自己账户中更合适的模型。
- **保留上下文，减少无谓重开会话。** 切换某个任务的通道不需要为此新建对话、重新说明背景或影响其他任务。它不会让同一请求天然少消耗 Token，但可以避免把不需要高成本模型的任务长期放在高成本通道，从而帮助控制额度与费用。
- **一次看完所有通道是否可用。** “全部检测”会逐个检测已配置供应商并汇总结果，定位 API Key、地址、协议、额度或限流问题，无需手动逐个切换测试。
- **个性化背景切换，静态或动态都能调。** 从本地选择图片、GIF 或 MP4 后，可一键启动 Codex 并应用背景；也可调大小、位置、显示方式、透明度、遮罩、磨砂、渐变和界面分区。动态媒体默认关闭，需要时再启用。

## 核心能力

### 单会话通道切换

- 为选中的已有会话设置**固定通道**，可指定供应商、模型与思考强度。
- 为选中的已有会话设置**跟随全局**，仅在主动操作时同步，不会因为之后切换全局通道而自动改写旧会话。
- 操作前显示将修改的会话、目标供应商、模型和思考强度，确认后才执行。
- 仅允许在 Codex 已完全退出时执行；先预检、备份，再通过 Codex app-server 尝试操作并校验结果。
- 不直接改写会话 SQLite 或 JSONL 来实现路由；失败时会尝试恢复原设置。
- 适合把高推理、低延迟、低成本或特定供应商能力按任务分开使用，前提是用户自己的供应商账户实际支持对应模型与能力。

这是非官方实验能力。供应商的区域、账号、额度、计费、模型支持和工具调用能力由对应服务决定。

### 个性化背景切换与本地外观实验

- 选择本地 PNG、JPG、WEBP、GIF 或 MP4，临时应用到当前 Codex 窗口；提供“启动 Codex 并应用背景”，避免每次手动打开后重新配置。
- 可调节背景大小、位置、显示方式、遮罩、各区域透明度、磨砂、渐变与标题栏等参数。
- 提供“背景清晰”和“无磨砂 · 文字清晰”预设；GIF、MP4 是默认关闭的高资源实验选项。
- 只连接本机 `127.0.0.1` 调试端口，只生成受控 CSS 和固定媒体层；不提供任意 JavaScript 注入，不修改 Codex 安装文件、账号或会话内容。
- 可一键恢复当前窗口原外观。关闭、刷新或更新 Codex 后效果可能失效，这是预期行为。

### 全局通道与供应商接入

- 管理新会话的全局默认通道。
- 支持当前 Codex 登录、原生 Responses API 和本地 Responses ↔ Chat Completions 协议翻译。
- 可添加/编辑供应商，拉取模型、检测协议，并通过“全部检测”一次汇总所有已配置通道的连接结果。
- 内置常用供应商和本地服务作为起始预设；预设不代表服务可用或得到服务方认可，以账户实际检测结果为准。
- API Key 使用 Windows DPAPI 按当前用户加密保存，不写入 `config.toml`、日志或远端服务。

### 会话归档与兼容修复

- 通过 Codex app-server 尝试归档和恢复会话，执行前自动备份。
- “修复已归档会话侧栏残留”只处理 `state` 中已确认 `archived=1` 的会话；会备份并验证 `state`、catalog 和 session index。
- 这是针对部分 Codex 版本侧栏残留现象的实验兼容修复，不会猜测或删除未知会话数据。

## 快速开始

1. 从 [Releases](../../releases) 下载 `Codex工具箱-0.1.0-beta-windows-x64.zip` 和同名 `.sha256` 文件。
2. 解压到任意目录，保持 `Codex工具箱.exe` 与 `Codex工具箱认证助手.exe` 在同一目录。
3. 启动 `Codex工具箱.exe`，添加供应商并使用“全部检测”确认连接。
4. 若只想影响新会话，在“通道切换”中选择供应商并切换全局默认。
5. 若要为已有会话指定通道，先完全退出 Codex，再进入“会话路由实验”，确认启用后选择会话并执行固定或跟随全局。

完整步骤、场景说明和常见问题见 [使用手册](docs/使用手册.md)。

## 功能边界

| 功能 | 适用范围 | 是否默认开启 | 关键限制 |
| --- | --- | --- | --- |
| 单会话通道切换 | 已有会话 | 否 | Codex 必须完全退出；非官方实验，按版本兼容 |
| 本地背景与外观 | 当前 Codex 窗口 | 否 | 仅 Windows，本地 CSS/CDP 实验，关闭或更新后可能失效 |
| 全局通道切换 | 之后新建的会话 | 是 | 不会自动改写已有会话 |
| 本地协议翻译 | 用户配置的第三方 API | 按供应商配置 | 仅支持可无损转换的能力；不支持时会停止并提示 |
| 归档/恢复与侧栏残留修复 | 已有会话 | 归档可用，修复按需 | 依赖当前 Codex 数据布局与 app-server 行为 |

## 系统要求

- Windows 10/11 x64，已安装 Codex 桌面版和 Microsoft Edge WebView2 Runtime。
- 会话路由、归档、恢复与侧栏残留修复前，必须完全退出 Codex，包括托盘残留进程。
- 本地外观实验需要 PowerShell 7 (`pwsh`)；缺失时工具箱会安全禁用该实验，不影响其他功能。
- 当前仅发布 Windows 测试包，macOS 尚未作为正式发布目标。

## 安全与责任

- 工具箱没有远程服务器。启用本地翻译时，请求内容会发送到自行配置的上游 API。
- 密钥只保存于当前 Windows 用户的数据保护范围内；不要复制自己的 `providers.json` 给其他人。
- 请自行遵守 OpenAI、第三方供应商与所在地区的规则。本项目不提供或宣传绕过登录、订阅、地区、权限或安全机制。
- 未签名测试版可能触发 Windows SmartScreen 的“未知发布者”提示。请只从本仓库 Release 下载，核对 SHA-256，不要运行第三方重打包文件。

详情见 [安全说明](SECURITY.md) 与 [隐私说明](PRIVACY.md)。发现问题请提交 [Bug 报告](../../issues/new?template=bug_report.yml)。

## 开发与测试

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
pwsh -File .\build.ps1
```

`build.ps1` 会生成 Windows x64 测试包及 SHA-256 校验文件。
