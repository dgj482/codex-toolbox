# Codex 工具箱使用手册

适用于 Windows x64 测试版 `0.1.5-beta`。本手册按常见任务组织：先配置通道，再为已有会话指定通道，最后再使用外观与会话管理功能。

> 会话路由、归档兼容修复和本地外观均不是 OpenAI 官方稳定功能。操作前先阅读界面提示；遇到版本不兼容时，不要反复执行同一操作，应保留工具箱显示的备份位置和错误信息。

## 1. 先理解三种范围

| 你要做的事 | 应使用的功能 | 会影响什么 |
| --- | --- | --- |
| 让之后新建的会话换一条通道 | 通道切换 | 仅之后新建的会话 |
| 让某个已有会话固定使用一条通道 | 会话路由实验 | 仅选中的会话 |
| 让某个已有会话与当前默认一致 | 会话路由实验的“同步到当前默认通道” | 仅选中的会话 |
| 清理已经归档但侧栏仍出现的会话 | 会话归档的兼容修复 | 仅 state 已确认归档的会话 |
| 个性化切换 Codex 窗口背景 | 实验外观 | 仅当前窗口，关闭/更新后可能失效 |
| 把英文 Codex 界面临时显示为中文 | 表层翻译 | 仅当前窗口的覆盖显示，不改原文与官方设置 |
| 中文提示词转成英文后发送 | 表层翻译 | 先预览确认，再写入官方输入框或发送 |

全局切换不会自动批量修改旧会话。单会话路由也不会改变全局默认通道。

## 亮点速览

- **按任务选模型：** 不同任务可以保留各自的供应商、模型和思考强度，不必为了切换模型新建会话或影响其他任务。
- **更容易控制成本：** 这不会让相同输入天然减少 Token；实际优势在于，简单任务可使用自己账户中更合适的低成本模型，复杂任务再使用高推理模型，避免一律使用高成本通道。
- **一次检测全部通道：** “全部检测”会逐个检测现有供应商并汇总结果，方便发现地址、Key、协议、额度或限流问题。
- **个性化背景切换：** 从本地选择图片、GIF、MP4 后，可一键启动 Codex 并应用；支持调整大小、位置、透明度、遮罩、磨砂与渐变。动态媒体占用资源更高，默认不启用。

## 2. 安装与首次启动

1. 下载 Windows x64 ZIP 与同名 `.sha256` 文件。
2. 解压 ZIP 到任意普通目录，运行其中唯一的 `Codex工具箱.exe`。
3. 双击 `Codex工具箱.exe`。首次启动会在当前用户的 `%LOCALAPPDATA%\CodexToolbox` 创建工具箱数据目录。
4. 如果 Windows 提示“未知发布者”，确认文件来自本仓库 Release 并已核对 SHA-256 后，再按系统提示打开。
5. 工具箱关闭窗口时默认会隐藏到托盘。需要完全退出时，在托盘菜单选择“退出”。

工具箱的供应商配置、路由记录和备份都在当前用户目录中；不会读取或覆盖开发者电脑的数据。

## 3. 配置并检测供应商

1. 打开“通道切换”，点击“添加供应商”。
2. 选择预设或手动填写名称、Base URL、模型和 API Key。
3. 上游只支持 Chat Completions 时，按界面说明启用本地翻译；原生 Responses API 不需要翻译。
4. 保存后选择该供应商，点击“全部检测”。报告会逐个显示连接结果，不会切换默认通道，也不会创建对话。
5. 检测成功后，再进行全局或单会话切换。

连接失败时按状态码处理：`401` 通常是 Key 无效，`403` 可能是权限或地区限制，`429` 可能是额度或限流。工具箱不会尝试绕过这些限制。

## 4. 最重要：为已有会话固定通道

### 操作前

1. 配置并检测目标供应商。
2. 完全退出 Codex，包括托盘中的残留进程。
3. 在工具箱打开“会话路由实验”。
4. 阅读风险说明后，勾选“启用会话路由实验”。这是一次明确授权，默认关闭。

### 固定到指定通道

1. 在左侧会话列表勾选一个或多个已有会话。
2. 在右侧选择“目标通道”；需要时填写本次固定使用的模型和思考强度。
3. 点击“固定到目标通道”。
4. 在确认框中核对会话数量、会话名称、供应商、模型和思考强度。
5. 确认后等待右侧状态区显示结果。完成后重新启动 Codex，再进入该会话验证显示的模型信息。

工具箱会先预检和备份，然后通过 Codex app-server 尝试写入。app-server 在某些版本中落盘较慢，因此状态区会持续显示进度；不要因为前几秒没有弹窗而重复点击。

### 同步到当前全局默认通道

步骤相同，但点击“同步到当前默认通道”。它只把本次选择的会话同步到**此刻**的全局默认，不会让它以后自动随所有全局切换变化。

### 失败时怎么处理

- 看状态区或错误提示中的备份位置，先保留备份。
- 检查 Codex 是否真的完全退出。
- 检查目标供应商是否已通过连接检测。
- 如果提示当前 Codex 版本未确认保存路由，请不要反复尝试；这表示该版本的 app-server 行为不兼容，等待工具箱更新更合适。

如果会话条目出现红色“模型残留”标签，可点击右侧“修复模型残留”。该按钮只会选中当前标红的会话，并把目标通道的默认模型显式提交给 Codex app-server；它仍然需要 Codex 完全退出，并会执行备份、落盘校验和失败回滚。若修复后仍标红，说明当前 Codex 版本没有可靠支持已有会话的模型重写，不要手动编辑 SQLite 或 JSONL，可保留备份并改用新会话。

## 5. 全局默认通道

全局默认通道只决定**之后新建的会话**：

1. 在“通道切换”选择供应商。
2. 点击“切换到选中”。
3. 完全重启 Codex。
4. 新建一个会话确认生效。

不要把全局切换当作“批量替换历史会话”。如果需要改历史会话，请使用第 4 节的会话路由实验。

## 6. 个性化背景切换与本地外观实验

### 使用步骤

1. 打开“实验外观”，确认并启用“本地外观实验”。
2. 选择本地图片、GIF 或 MP4。
3. 先使用“启动 Codex 并应用背景”；需要边调边看时再点击“启动 Codex 并开启实时调节”。
4. 按“背景画面”“界面通透”“细节与动态媒体”调整参数。每项下方都有作用范围说明。
5. 不想保留效果时点击“恢复 Codex 原外观”。

在“界面通透”中还可以设置“会话标题栏位置”。它对应 Codex 正文上方显示会话名称的那一条栏（例如“工具箱 (2)”），不是左侧会话列表的置顶：选择“顶部栏占位”会让标题栏进入页面布局，不再覆盖正文；也可以恢复悬浮或隐藏。

### 参数怎么选

| 目标 | 建议 |
| --- | --- |
| 背景完整显示 | 图片显示方式选“完整显示”，再调节宽度和高度 |
| 背景铺满窗口 | 图片显示方式选“铺满窗口”，宽度和高度均设为 100% |
| 背景清晰 | 点击“背景清晰”预设 |
| 不模糊但文字清楚 | 点击“无磨砂 · 文字清晰”预设 |
| 减少视频资源占用 | 不启用 MP4；GIF 控制在 3 MB 内，MP4 控制在 30 MB 内 |

这是 Windows 本地实验。它只作用于当前 Codex 页面，不会修改 WindowsApps、`app.asar`、Codex 配置、账号或会话内容。Codex 关闭、刷新、更新或 DOM 变化后效果消失是正常的。

## 7. Codex 表层双向翻译实验

1. 先在“通道切换”配置并检测一个可用的第三方或本地 API 通道。官方登录不向工具箱提供可复用 API Key，不能作为动态翻译通道。
2. 打开“表层翻译”，阅读说明并勾选启用实验。
3. “覆盖翻译菜单和按钮”使用本地词典，不产生 API 请求；“覆盖翻译英文对话内容”和“中→英翻译”会把相应文字发送到所选通道。
4. 首次点击“启动 Codex 并开启翻译”。Codex 会关闭后以本机临时调试端口重启，但官方设置、安装文件和会话数据不变。
5. 在提示词框输入中文，点击新增的“中→英翻译”，检查并编辑英文预览，然后选择“仅写入”或“写入并发送”。普通输入和官方发送按钮仍可照常使用。
6. 点击“关闭表层翻译”会移除覆盖层。若工具箱异常退出，重启 Codex 也会清除本次临时效果。

翻译脚本只在当前页面内存中临时替换符合条件的可见文字节点，并保留原值；点击“原文”会立即恢复。动态页面结构可能让少量文字未被识别；这属于页面适配问题，不代表安装文件、官方语言设置或会话内容被修改。

## 8. 归档、恢复与侧栏残留修复

### 归档与恢复

1. 完全退出 Codex。
2. 打开“会话归档”，勾选目标会话。
3. 点击“归档选中”或“恢复选中”。
4. 工具箱会在操作前备份并在操作后校验；完成后再启动 Codex 检查侧栏。

### 已归档会话仍出现在侧栏

若已确认归档成功，但重启后侧栏仍有残留：

1. 保持 Codex 完全退出。
2. 点击“修复已归档会话侧栏残留”。
3. 工具箱只从 `state` 筛选 `archived=1` 的会话 ID，再受限地清理对应 catalog/index 项并验证。

该操作不会删除未归档会话，也不会对未知记录做批量猜测。出现错误时停止操作，并保留已显示的备份位置。

## 9. 常见问题

### 单会话路由很慢，或成功后没有弹窗

会话路由需要等待 Codex app-server 异步落盘并校验。请看右侧状态区，等待其显示成功、失败或兼容性提示；不要连续点击同一个操作按钮。若状态提示未确认，请保留备份并停止重复尝试。

### 工具箱显示供应商或会话为空

等待启动完成。界面会自动等待本机桥接对象可用并重试读取；如果仍为空，打开“本地诊断”核对数据目录、供应商数量与 Codex 运行状态。

### 背景没有保留

背景是临时注入到当前 Codex 窗口的本地实验。请通过工具箱的“启动 Codex 并应用背景”启动；手动启动或 Codex 更新后，需要重新应用。

### 为什么某个第三方模型不能使用工具

本地翻译仅转换文本和 `function` 调用。网页搜索、文件搜索、图片等无法无损转换的能力会停止并提示；请改用原生 Responses API 或当前 Codex 登录通道。

## 10. 隐私、安全与反馈

- 工具箱没有自己的远程服务；第三方通道请求只会发往自行配置的上游。
- API Key 使用 Windows DPAPI 保存，不会写入日志或子进程命令行。
- 反馈问题时，请隐藏 API Key、会话内容、账号信息和本地绝对路径。
- 提交前可阅读 [安全说明](../SECURITY.md)、[隐私说明](../PRIVACY.md) 和 [更新日志](../CHANGELOG.md)。
