## 短标题

Codex 工具箱：给不同已有会话固定不同模型通道

## 中文发布帖

我做了一个 Windows 本地工具 `Codex 工具箱`，用于把 Codex 的全局默认通道和已有会话的单独通道分开管理。

它解决的是一个实际工作流问题：全局切换适合之后新建的会话，但一个正在进行中的代码任务、研究任务和轻量整理任务，未必都适合使用同一条通道。工具箱可以在 Codex 完全退出后，为指定已有会话尝试固定供应商、模型和思考强度；也可以手动同步回当前全局默认，不会自动改写其他会话。

当前测试版还包括：

- 一键检测全部已配置通道的连接、协议、额度或限流状态；
- 本地图片、GIF、MP4 个性化背景，可调整大小、位置、透明度、遮罩、磨砂和渐变；
- 归档、恢复及“已归档会话侧栏残留”的受限兼容修复；
- Windows DPAPI 本地加密保存 API Key，不写入日志或命令行。

这是社区项目，不是 OpenAI 官方产品。会话路由和本地外观均为默认关闭的实验功能，Codex 更新后可能需要适配；请自行遵守 OpenAI、第三方供应商与所在地区的规则。

## English post

I built a Windows-local toolbox for people who use multiple Codex tasks and provider configurations.

Its main feature is **per-session routing**: when Codex is fully closed, an existing task can be set to a selected provider, model, and reasoning level, or manually synchronized to the current global default. Changing one task does not automatically overwrite other tasks.

The beta also includes an all-provider connectivity check, local customizable image/GIF/MP4 background experiments, and guarded archive/restore helpers.

This is an unofficial community project. Per-session routing and local appearance are opt-in experiments and may need updates after Codex changes. It does not bypass account, region, subscription, permission, or security controls.
